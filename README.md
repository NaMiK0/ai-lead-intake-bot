# Lead-Intake Bot

Telegram-бот для приёма заявок IT-студии. Клиент пишет одним сообщением, как
удобно, в свободной форме — бот через LLM превращает это в структурированную
заявку (кто клиент, контакт, что хочет, насколько срочно) и отвечает карточкой.

## Пример

Клиент пишет:

> Здравствуйте! Меня зовут Игорь, нужна CRM для отдела продаж, чтобы вести
> клиентов и сделки. Хотелось бы успеть за пару недель. Телефон 8 900 123-45-67

Бот отвечает карточкой:

```
📇 Заявка
Клиент:    Игорь
Контакт:   8 900 123-45-67
Категория: CRM
Запрос:    CRM для отдела продаж, ведение клиентов и сделок
Дедлайн:   пара недель
🟡 Срочность: средняя — конкретное намерение заказать, дедлайн не жёсткий
```

Если в сообщении несколько разных заявок (в том числе для разных людей) —
бот вернёт по карточке на каждую. Если сообщение не заявка (благодарность,
оффтоп) — вернёт короткое пояснение вместо карточки.

## Стек и почему так

- **aiogram 3** — Telegram-бот, long polling.
- **openai SDK → OpenRouter** — LLM-клиент; OpenRouter полностью совместим с
  OpenAI Chat Completions API, даёт доступ к бесплатным моделям. Извлечение —
  через **нативный tool calling** (`tool_choice` форсирует вызов инструмента
  `submit_extraction`), а не парсинг текста в поисках JSON. Каскад из
  нескольких бесплатных моделей — если одна недоступна/ошиблась, идёт
  следующая (модели живьём протестированы и выбраны по качеству, см.
  `bot/config.py`).
- **Pydantic** — второй, независимый от модели уровень валидации структуры
  ответа (типы, допустимые значения категорий/срочности, обязательные поля).
- **Postgres (`asyncpg`, без ORM)** — источник правды по заявкам. Ручной SQL:
  меньше зависимостей, весь запрос виден прямо в коде.
- **Qdrant + `fastembed`** — RAG: перед классификацией бот ищет похожие по
  смыслу прошлые заявки и передаёт их модели как контекст. Эмбеддинги —
  `fastembed` (ONNX через `onnxruntime`, без `torch` — легче для деплоя на
  бесплатный тариф), мультиязычная модель, понимает русский текст.
- **MCP** (`mcp` SDK) — локальный сервер, оборачивающий чтение тех же данных
  (`find_lead`, `similar_leads`) как MCP tools для клиентов вроде Claude
  Desktop. Не часть обработки сообщений ботом — отдельный, необязательный
  интерфейс (подробнее — [ниже](#mcp-сервер)).

## Как это устроено

```
Telegram ──▶ aiogram (bot/handlers.py)
                  │
                  │ 1. похожие прошлые заявки (RAG, необязательно)
                  ▼
             bot/rag ──▶ Qdrant (эмбеддинги)
                  │
                  │ 2. текст + контекст похожих заявок
                  ▼
             bot/llm ──▶ OpenRouter (каскад моделей, tool calling)
                  │
                  │ 3. structured tool-call result
                  ▼
        Pydantic-валидация (bot/models.py)
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
   карточка клиенту   bot/storage ──▶ Postgres (источник правды)
                          │
                          └──▶ bot/rag: вектор новой заявки → Qdrant

MCP-сервер (bot/mcp) — отдельно, читает Postgres/Qdrant по запросу
MCP-клиента (например Claude Desktop); в обработке сообщений не участвует.
```

RAG и MCP — необязательные контуры: если Qdrant недоступен, бот продолжает
принимать и сохранять заявки как обычно, просто без контекста похожих.

## Структура проекта

```
bot/
├── config.py     # переменные окружения, константы
├── models.py     # pydantic-схема заявки
├── llm.py        # вызов LLM с каскадом фолбэков + RAG-контекст
├── dedup.py      # дедуп сообщений (in-memory)
├── rendering.py  # карточки для Telegram
├── handlers.py   # aiogram-хэндлеры
├── app.py        # сборка и запуск бота
├── storage/      # персистентность заявок (Postgres, asyncpg, без ORM)
├── rag/          # эмбеддинги (fastembed) и поиск похожих заявок (Qdrant)
└── mcp/          # MCP-сервер поверх storage/rag (find_lead, similar_leads)
main.py             # точка входа
docker-compose.yml  # локальные Postgres + Qdrant для разработки
```

## Быстрый старт

Нужны: Python 3.11+, Docker (для локальных Postgres/Qdrant), токен
Telegram-бота, ключ OpenRouter.

```bash
git clone https://github.com/NaMiK0/ai-lead-intake-bot.git
cd ai-lead-intake-bot

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt

docker compose up -d postgres qdrant

cp .env.example .env             # и подставь свои значения (см. ниже)

set -a && source .env && set +a  # Windows (PowerShell): задай переменные окружения вручную
python main.py
```

Бот стартует через long polling — напиши ему в Telegram что-нибудь вроде
примера выше и проверь, что приходит карточка.

При первом запуске модель эмбеддингов для RAG (~225 МБ) скачивается один раз
и кэшируется — старт может занять чуть дольше обычного.

## Переменные окружения

См. `.env.example`. Коротко:

| Переменная            | Обязательна | Назначение                                                                 |
|------------------------|:-----------:|-----------------------------------------------------------------------------|
| `TELEGRAM_BOT_TOKEN`   | да          | Токен от [@BotFather](https://t.me/BotFather).                              |
| `OPENROUTER_API_KEY`   | да          | Ключ с [openrouter.ai/keys](https://openrouter.ai/keys).                    |
| `DATABASE_URL`         | да          | Строка подключения к Postgres. Схема создаётся автоматически при старте.    |
| `RAG_ENABLED`          | нет         | `true` (по умолчанию) / `false`. См. [ограничения](#известные-ограничения). |
| `QDRANT_URL`           | нет         | URL Qdrant для RAG. По умолчанию — локальный (`http://localhost:6333`).     |
| `QDRANT_API_KEY`       | нет         | Нужен только для облачного Qdrant; для локального — оставить пустым.        |
| `BOT_MODE`             | нет         | `polling` (по умолчанию, локально) / `webhook` (прод).                      |
| `WEBHOOK_URL`,`WEBHOOK_SECRET`,`PORT` | нет | Только для `BOT_MODE=webhook` — см. `.env.example`.            |

Если `QDRANT_URL` недоступен (или `RAG_ENABLED=false`) — бот всё равно
работает, просто без похожих прошлых заявок в контексте LLM.

## MCP-сервер

`bot/mcp/server.py` — тонкая обёртка `find_lead`/`similar_leads` как MCP
tools. Не участвует в обработке сообщений Telegram-ботом — отдельный,
необязательный интерфейс для чтения тех же данных из MCP-клиента (например
Claude Desktop). Локальный, stdio-транспорт: клиент сам запускает процесс,
поднимать сервер отдельно не нужно.

Подключение из Claude Desktop — в `claude_desktop_config.json` (Settings →
Developer → Edit Config):

```json
{
  "mcpServers": {
    "lead-bot": {
      "command": "/path/to/ai-lead-intake-bot/.venv/bin/python3",
      "args": ["-m", "bot.mcp.server"],
      "cwd": "/path/to/ai-lead-intake-bot",
      "env": {
        "DATABASE_URL": "postgresql://lead_bot:lead_bot@localhost:5432/lead_bot",
        "QDRANT_URL": "http://localhost:6333"
      }
    }
  }
}
```

Требует запущенных локальных `postgres`/`qdrant` (`docker compose up -d`).
После правки конфига — перезапустить Claude Desktop.

## Деплой

Прод — [Render](https://render.com) (бесплатный web-сервис, webhook-режим) +
[Neon](https://neon.tech) (Postgres). Деплой — через `render.yaml`
(Render Blueprint), а не ручную настройку в дашборде:

1. Neon: создать проект, взять **прямую (Direct/Unpooled)** строку
   подключения — не Pooled: `asyncpg` использует серверные prepared
   statements, которые конфликтуют с транзакционным пулингом PgBouncer у
   Neon по умолчанию.
2. Render → **New → Blueprint** → указать этот репозиторий. Render найдёт
   `render.yaml` и попросит ввести секреты (`TELEGRAM_BOT_TOKEN`,
   `OPENROUTER_API_KEY`, `DATABASE_URL`) — без кавычек, в отличие от `.env`.
   Остальное (`BOT_MODE=webhook`, `WEBHOOK_SECRET`, порт) проставится само.
3. Deploy Blueprint. `WEBHOOK_URL` брать не нужно — берётся из
   `RENDER_EXTERNAL_URL`, который Render проставляет сам.

### Известные ограничения

- **RAG выключен на бесплатном тарифе Render** (`RAG_ENABLED=false` в
  `render.yaml`). Причина — измерено вживую: модель эмбеддингов при загрузке
  реально потребляет ~600 МБ RAM (не помогают ни `threads=1`, ни отключение
  memory arena onnxruntime), а лимит бесплатного тарифа — 512 МБ, процесс
  падает по OOM ещё до подключения к Qdrant. RAG полностью рабочий и
  проверенный локально (см. выше) — на проде это осознанный компромисс
  ресурсов бесплатного хостинга, а не недоделанная фича; сам приём и
  сохранение заявок эту особенность никак не задевает.
- Бесплатный Render засыпает при простое — первый запрос после паузы может
  обрабатываться на несколько десятков секунд дольше обычного.
